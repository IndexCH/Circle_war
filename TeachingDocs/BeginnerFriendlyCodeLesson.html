圆形地图代码课：写给 Unity 新手

这节课我们一起读懂一个小项目：屏幕中间有一个圆圈，圆圈上排着 12 个格子，人物站在圆圈最低点不动。 你按方向键，圆圈就会转一格，看起来就像人物在沿着一条路往前走。这条路一共 30 段，走完就进入“大地图”。

我们的目标不是写得多酷，而是每一行代码你都能看懂、能讲出来、能自己改。

一、重构前有什么问题？

原来所有逻辑都挤在一个 700 多行的脚本里。它一个人干了太多活：

  • 用代码画图片
  • 计算 30 段路的数据
  • 搭建场景（背景、圆圈、格子、人物）
  • 读键盘、转圆圈、进大地图

这就像一个人既当厨师、又当服务员、又当收银员。出问题时你根本不知道该看哪一段。 对新手来说，最大的麻烦是：“数据”和“画面”混在一起，分不清谁是谁。

这次重构做了两件最重要的事：
1. 数据和表现分开：先算清楚“路上有哪些段”，再单独去管“怎么把它画出来”。
2. 一个大脚本拆成几个小脚本：每个脚本只干一件事，名字一看就知道它负责什么。

二、重构后的代码阅读顺序

建议按下面的顺序读，从“最简单的数据”一步步读到“总指挥”：

  1. 数据CircleRoadSegmentData.cs —— 先搞清楚“一段路”长什么样。
  2. 资源CircleSegmentSpriteFactory.cs —— 看看图片是怎么用代码画出来的。
  3. 数据CircleRoadMapBuilder.cs —— 看 30 段路是按什么规则造出来的。
  4. 表现CircleMapSegment.cs —— 看“一个格子”怎么把图片显示出来。
  5. 总指挥CircleMapRecyclerViewDemo.cs —— 最后看它怎么把上面这些串起来。

三、每个脚本负责什么？

脚本它负责什么一句话比喻
CircleRoadSegmentData记录一段路的名字、图片、颜色一张“格子卡片”
CircleSegmentSpriteFactory用代码生成圆点图片，并负责清理画图片的小工厂
CircleRoadMapBuilder按规则造出 30 段路的数据关卡设计师
CircleMapSegment把交给它的一段数据显示成画面一个会换装的格子
CircleMapRecyclerViewDemo搭场景、收键盘、转圆圈、刷新显示总指挥
为什么数据类不是 MonoBehaviour？
MonoBehaviour 是“能挂在 GameObject 上的脚本”。 但像 CircleRoadSegmentData 这种只用来存数据的类，不需要挂到物体上， 所以它就是一个普通 C# 类。新手记住：只有要挂到物体上、要用 Start/Update 的脚本，才需要继承 MonoBehaviour。

四、核心变量解释

总指挥里几个最关键的变量

  • currentRoadSegmentIndex：玩家现在走到第几段（从 0 开始）。
  • targetCircleAngle：圆圈“想要”转到的角度，圆圈每帧慢慢转过去。
  • roadSegmentList：整条路的数据（30 段），和屏幕上的格子是两回事。
  • visibleSegmentList：屏幕上真实存在的 12 个格子。
  • hasEnteredBigMap：是否已经走完全程、切到了大地图。
核心思想：12 个格子，30 段数据。
我们不会真的造出 30 个物体，而是只造 12 个格子，转动时不断告诉它们“现在改显示哪一段数据”。 这就是为什么数据和表现要分开——同一个格子，换不同数据，就能表现不同的路。

五、核心方法解释

1. 数据怎么造出来（CircleRoadMapBuilder）

用一连串简单的 if 决定第几段是什么类型。故意不写得“聪明”，就是为了能一条条念出来：

// 前 7 段都是树林路，作为平缓开局
if (index <= 6)
{
    return new CircleRoadSegmentData("树林道路 " + index, spriteFactory.treeSegmentSprite, ...);
}

// 中间段：每 6 段一个循环，轮流出现不同类型
int patternIndex = index % 6;
if (patternIndex == 0) { // 采集资源点 ... }
if (patternIndex == 1) { // 沿路探索 ... }

2. 圆圈怎么平滑旋转（RotateCircleTowardTarget）

float currentAngle = circleRotatingRoot.localEulerAngles.z;
float newAngle = Mathf.LerpAngle(currentAngle, targetCircleAngle, Time.deltaTime * circleRotateSpeed);
circleRotatingRoot.localEulerAngles = new Vector3(0f, 0f, newAngle);

每一帧只往目标角度靠近一点点，于是看起来就是平滑转动，而不是“啪”地一下跳过去。

3. 格子怎么换显示（CircleMapSegment）

总指挥把一段数据“递给”格子，格子负责换图片、换颜色、决定要不要放大（玩家所在格子会放大一点）。 格子自己不知道整条路有 30 段，它只管显示别人给它的那一段。这就是“各管各的”。

六、Unity 生命周期讲解

方法什么时候被调用本项目里用来做什么
Start()游戏开始时，只调用一次开局自动搭建整个场景
Update()每一帧都调用读键盘 + 让圆圈转一点
Awake()比 Start 更早，物体一创建就调用格子脚本自己找好 SpriteRenderer
OnDestroy()物体被销毁时清理代码生成的图片
Update 里为什么这么干净？
看总指挥的 Update，里面只有两行：ReadKeyboardInput(); 和 RotateCircleTowardTarget();。 这是好习惯：Update 只写“要做哪几件事”，具体怎么做，藏进各自的小方法里。这样一眼就能看懂每帧在干嘛。

七、新手容易犯错的地方

  • 把 deltaTime 忘了：移动/旋转不乘 Time.deltaTime，在不同帧率的电脑上速度会不一样。
  • 代码生成的图片忘了删：new Texture2D、Sprite.Create 出来的东西 Unity 不会自动回收，要自己 Destroy，否则内存会越用越多。
  • 分不清数据和表现：记住 roadSegmentList 是数据（30 段），visibleSegmentList 是画面（12 个格子）。
  • GetComponent 找不到组件：人物图片常在子物体上，所以要用 GetComponentInChildren 而不是 GetComponent。
  • sortingOrder 顺序搞反：数字越小越靠后。背景设成 -20，人物设成 20，人物才会盖在背景上面。

八、课堂提问

Q1：为什么屏幕上只有 12 个格子，却能表现 30 段路？

因为转动时我们只是不停地把不同数据“塞”给这 12 个格子去显示。

Q2：CircleRoadSegmentData 为什么不继承 MonoBehaviour？

因为它只是存数据，不需要挂在 GameObject 上，也不需要 Start/Update。

Q3：如果删掉 Time.deltaTime 会发生什么？

圆圈旋转速度会随帧率变化，高帧率电脑转得飞快，低帧率电脑转得很慢。

Q4：总指挥的 Update 为什么只有两行？

因为每帧要做的具体事情都被拆进了小方法，Update 只负责“按顺序喊它们干活”。

九、课后练习

  1. 改颜色：在 CircleRoadMapBuilder 里把“遭遇敌人”那段的颜色改成你喜欢的颜色，运行看看变化。
  2. 改路长：在 Inspector 把 totalRoadSegmentCount 从 30 改成 15，观察提前进入大地图。
  3. 加按键：在 ReadKeyboardInput 里加一个按 R 键调用 Build() 重新开始的功能。
  4. 加新格子类型：在工厂里再生成一种颜色的圆点，并在 Builder 里让某些段用上它。
  5. 试着讲一遍：对着同桌，用自己的话把“12 个格子表现 30 段数据”讲清楚。
