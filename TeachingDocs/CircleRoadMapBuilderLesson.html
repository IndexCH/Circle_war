造出整条路的数据：CircleRoadMapBuilder 详解

这节课讲的脚本是一个“关卡设计师”：它不画任何东西，只负责算出整条路有哪 30 段、每段是什么类型、什么颜色、上面有没有内容。 算完交给别人去显示。这就是“数据和表现分离”——先把数据准备好，再谈怎么画。本页有 3 个会动的演示，帮你看懂 for 循环、% 6 取余、和一串 if 是怎么配合的。

一、这个脚本是干嘛的？

输入 → 输出：

  • 输入：一共多少段（30），以及一批做好的图片（来自图片工厂）。
  • 输出：一个装着 30 条 CircleRoadSegmentData 的列表（List）。

它完全不碰屏幕，不 new GameObject，只是“算数据”。所以它是普通 C# 类，不是 MonoBehaviour。

名词解释：List（列表）。
List 就是一个能自动伸缩的格子队列，可以一个一个往里塞东西（Add），塞完用下标取出来。这里我们往列表里塞 30 段路的数据。

二、动画演示①：for 循环怎么把列表“一段一段”造出来

核心代码就这几行——一个 for 循环，从第 0 段走到第 29 段，每走一步就造一条数据塞进列表：

for (int index = 0; index < totalRoadSegmentCount; index++)
{
    CircleRoadSegmentData roadSegment = CreateRoadSegmentByIndex(index, ...);
    roadSegmentList.Add(roadSegment);   // 塞进列表
}
return roadSegmentList;

每一格就是列表里的一条数据：上面是第几段，中间是名字和颜色圆点，底下的小标签表示这一段有没有“内容”（资源点 / NPC / 怪物）。

三、动画演示②：% 6 取余 —— 让题目“每 6 段循环一次”

中间这些段（第 7 段到倒数第二段），用 index % 6（取余数）让 6 种类型轮流出现：

int patternIndex = index % 6;   // 余数永远是 0~5，循环出现
if (patternIndex == 0) ... // 资源点
if (patternIndex == 1) ... // NPC
if (patternIndex == 2) ... // 事件
if (patternIndex == 3) ... // 怪物
if (patternIndex == 4) ... // 设施
else               ... // 关系（patternIndex == 5）
▶ 点“播放”，看 index 增加时，余数怎么在 0~5 之间循环
当前 index = 7
7 % 6 = 1 → NPC
高亮的那一格 = 当前余数落在的类型
取余（%）是什么？
a % b 就是“a 除以 b 剩下的余数”。比如 7 % 6 = 1、12 % 6 = 0、13 % 6 = 1。 余数永远在 0 ~ b-1 之间，所以 % 6 会让结果在 0、1、2、3、4、5 之间不停循环——这正好用来“每 6 段换一轮题型”。

四、动画演示③：一串 if 怎么决定“这一段是什么”

给一个 index，代码会从上往下逐条问 if，命中哪条就用哪条、然后 return 停下。点下面的按钮试试不同的 index：

if (index ≤ 6) → 树林道路（绿色，平缓开局）
if (index == 最后一段) → 年度危机 / 出口（金色）
else if (index % 6 == 0) → 采集资源点（+蓝方块标记）
else if (index % 6 == 1) → 沿路探索（NPC，+白长方标记）
else if (index % 6 == 2) → 触发事件
else if (index % 6 == 3) → 遭遇敌人（怪物）
else if (index % 6 == 4) → 建设设施
else → 推进关系（index % 6 == 5）
顺序很重要！ 这些 if 是从上往下判断的，命中第一条就返回。 所以“树林道路（index ≤ 6）”和“最后一段”要写在前面——它们是特例，必须先拦下来，否则就会被后面的 % 6 规则错误地处理。

五、方法讲解

BuildRoadSegmentList(总段数, 图片工厂)

对外的主方法。建一个空列表，用 for 循环造 30 段塞进去，最后把列表返回。就是演示①。

CreateRoadSegmentByIndex(index, 总段数, 图片工厂)

“出题逻辑”。给一个 index，用一串 if 决定它是什么类型、用哪张图、什么颜色，部分段还会标上 contentType（资源点 / NPC / 怪物）。就是演示②③。

“先造数据，再标内容”的写法。
资源点 / NPC / 怪物这几段，代码是先 new 出数据，再单独写一行 xxx.contentType = ...;。 这样读起来很清楚：“这是一段路，并且它上面有个资源点。”比一行塞进构造方法更好讲。

六、核心变量 / 概念

名字含义
index当前在造第几段（0 ~ 29）。
totalRoadSegmentCount一共多少段（这里是 30）。用它判断“最后一段”。
patternIndexindex % 6 的结果（0~5），决定中间段轮到哪种题型。
roadSegmentList造好的整条路，最后返回给调用者。
contentType这一段上有什么内容（资源点 / NPC / 怪物 / 无）。

七、新手容易困惑的地方

  • 把特例写在 % 6 后面：那样“树林”和“最后一段”会被普通规则覆盖。记住——特例先判断。
  • 分不清 index 和 patternIndex：index 是绝对位置（0~29），patternIndex 是余数（0~5），名字不一样。
  • 以为它会显示图片：这个脚本只算数据，不画任何东西。画图是别的脚本的事。
  • contentType 默认是 None：没有手动赋值的段（事件、设施、关系、树林）就是 None，不会有标记。

八、课堂提问

Q1：为什么用 for 循环而不是手写 30 行？

因为 30 段规律相同，循环一句就能搞定，还方便改成别的数量。

Q2：index % 6 的结果范围是多少？

永远是 0、1、2、3、4、5，所以题型每 6 段循环一次。

Q3：第 12 段是什么类型？

12 不 ≤ 6、也不是最后一段，12 % 6 = 0 → 采集资源点（带蓝方块标记）。

Q4：这个脚本会把路画到屏幕上吗？

不会。它只产出数据，画图交给别的脚本——这就是数据和表现分离。

九、课后练习

  1. 把“前 7 段都是树林”改成“前 3 段”，运行看开局变化（改 index <= 6）。
  2. 把循环周期从 % 6 改成 % 4，想一想题型会怎么变（注意 if 分支数量要对应）。
  3. 给“建设设施”那段也加一个 contentType（比如新增一种类型），让它也带标记。
  4. 用自己的话讲清楚：为什么“最后一段”的判断必须写在 % 6 之前。
