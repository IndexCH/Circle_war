用代码画图片：CircleSegmentSpriteFactory 详解

这节课只讲一个脚本：圆点图片工厂。它最特别的地方是——这些图片不是美术画的 png，而是程序用代码一个像素一个像素“画”出来的。 学完你会明白：一张图片，本质上就是“一格一格的颜色”。本页里有几个会动的小演示，帮你看懂代码到底在干什么。

一、这个脚本是干嘛的？

一句话：它负责“生产图片”和“用完清理图片”，别的什么都不管。

  • 生产 8 种圆点图片（树林、空地、资源、事件、敌人、设施、危机、出口）。
  • 生产 2 种内容标记图片（NPC 白色长方形、资源点蓝色正方形）。
  • 游戏结束时，把这些图片全部删除，不留垃圾。

它不知道哪一段路用哪张图（那是 CircleRoadMapBuilder 的事）。这就是“各管一摊”：工厂只管造，别人来取。

名词先解释：什么是 Sprite？
Sprite（精灵图）就是 Unity 里“能显示在 2D 画面上的一张图片”。你在游戏里看到的每个圆点、每个标记，都是一个 Sprite。

二、先认识 4 个关键概念

名词大白话解释
Texture2D一张“可以逐格涂色”的图片，像一张方格纸。每一格就是一个像素。
SetPixel(x, y, 颜色)给第 x 列、第 y 行那一格涂上颜色。
texture.Apply()“确认提交”。你涂完所有格子后，必须调用它，图片才真正生效。
忘了调用 = 图片是空白的。
Sprite.Create(...)把这张方格纸（Texture2D）包装成 Unity 能直接显示的 Sprite。

三、动画演示①：代码是怎么“一格一格画圆”的

看下面的代码骨架——这是 CreateSimpleDiscSprite 的核心。两层 for 循环，一行一行、一列一列地走过每个像素：

for (int y = 0; y < textureSize; y++)        // 一行一行往上走
{
    for (int x = 0; x < textureSize; x++)    // 每行里一列一列往右走
    {
        float distanceToCenter = 这个点到圆心的距离;
        if (distanceToCenter <= 外圈半径) {
            if (distanceToCenter >= 内圈半径) 涂边框色;
            else 涂填充色;
        }
        // 圆外面就不涂，保持透明
        texture.SetPixel(x, y, pixelColor);
    }
}

填充色（圆心附近）
边框色（外面一圈）
透明（圆外，不涂）

观察重点：扫描是从下到上、从左到右逐格进行的（对应两层 for 循环）；每一格都现场判断“它离圆心多远”，从而决定涂什么色。真实代码里方格纸是 96×96，这里缩小成 24×24 方便看。

核心思想：图片 = 一格一格的颜色判断。
画圆没有什么魔法，就是问每个像素一句话：“你离圆心多远？在里面就涂色，在外面就别涂。”这就是 distanceToCenter 那几行 if 在做的事。

四、动画演示②：圆的“三层结构”

每个圆点其实分三层，由“到圆心的距离”决定：

  • 最外层（棋盘格）：距离 > 外圈半径 → 透明，什么都不画。
  • 中间深色环（闪动的那圈）：在内圈和外圈之间 → 涂边框色。
  • 中心亮色：距离 < 内圈半径 → 涂填充色。

代码里这三层就是 outerRadius、innerRadius 两个数加上嵌套的 if 判断出来的。

五、动画演示③：矩形标记的“宽高比”

NPC 和资源点的标记用的是 CreateSimpleRectangleSprite，靠两个 0~1 的比例数字决定形状：

// 又窄又高 → 像一个站着的人（NPC）
npcMarkerSprite = CreateSimpleRectangleSprite("Npc Marker", Color.white, 0.42f, 0.82f);

// 宽高一样 → 正方形（资源点）
resourceMarkerSprite = CreateSimpleRectangleSprite("Resource Marker", 蓝色, 0.66f, 0.66f);
NPC：0.42 × 0.82
（窄而高的白长方形）
资源点：0.66 × 0.66
（蓝色正方形）

矩形的画法比圆更简单：不用算距离，只要判断“这个像素的 x 在不在左右边界之间、y 在不在上下边界之间”，在范围里就涂色。

左边白色长方形会上下“呼吸”，提示你：改 heightRatio 就能改高矮。

六、字段（变量）讲解

字段作用
treeSegmentSprite 等 8 个8 种圆点图片。字段名直接说明它代表哪种格子，取用时一目了然。
npcMarkerSprite / resourceMarkerSprite叠在格子上的内容标记图片。
generatedSpriteList一个清单，记下每一张代码生成的图片，方便最后统一删除。
为什么用 public 字段直接暴露图片？因为这是教学代码，简单直接最重要：别的脚本写 spriteFactory.treeSegmentSprite 就能拿到，不绕弯子。

七、方法讲解

CreateAllSegmentSprites()

“总开关”：一口气把 8 个圆点 + 2 个标记都生成出来。每一行就是“造一张图，存进对应字段”。老师可以一行一行念颜色。

CreateSimpleDiscSprite(名字, 填充色, 边框色)

画一个“实心圆 + 边框”。就是演示①和②讲的：两层 for 循环逐像素，按到圆心的距离决定涂什么色，最后 Apply() + Sprite.Create()。

CreateSimpleRectangleSprite(名字, 颜色, 宽比, 高比)

画一个“居中实心矩形”。和圆几乎一样，只是判断条件从“距离”换成“x、y 在不在矩形范围里”。

DestroyAllSegmentSprites()

把清单里所有图片连同它们的 Texture 一起删掉。运行时用 Destroy，编辑器里用 DestroyImmediate。

八、新手最容易踩的坑

  • 忘了 texture.Apply()：涂了半天像素，结果图片全空白。Apply 是“保存生效”的那一步。
  • 忘了清理：用 new Texture2D / Sprite.Create 生成的图片，Unity 不会自动回收，必须自己 Destroy，否则反复 Build 会越占越多内存。
  • 这个慢方法别用在每帧：逐像素画 96×96 = 9216 个格子，很慢。只适合开局生成一次，千万别放进 Update。
  • x 和 y 别搞反：SetPixel(x, y, ...) 里 x 是列、y 是行，y=0 在最底下。

九、课堂提问

Q1：为什么说“图片就是一格一格的颜色”？

因为 Texture2D 就是一张方格纸，SetPixel 一格一格涂，涂完就是一张图。

Q2：圆是怎么画出来的？用了什么判断？

对每个像素算它到圆心的距离，距离小就涂填充色，距离在中间就涂边框色，太远就透明。

Q3：Apply() 不调用会怎样？

你涂的颜色不会生效，图片是空白的。

Q4：为什么这个脚本不是 MonoBehaviour？

它不需要挂在物体上，也不用 Start/Update，只是个“工具类”，所以是普通 C# 类。

十、课后练习

  1. 把某个圆点的填充色改成你喜欢的颜色，运行看变化。
  2. 把 innerRadius 那行的 - 7f 改成 - 20f，观察边框变粗。
  3. 仿照 CreateSimpleRectangleSprite，给怪物加一张红色正方形标记（提示：再加一个 monsterMarkerSprite 字段并生成它）。
  4. 试着用自己的话，对同桌讲清楚“为什么必须调用 Apply()”。
